根因记录

#现象分类处置
1S1 首次执行返回 runtime.rejected: java.lang.NoClassDefFoundError: io/grpc/Context environment 本次搭建的 provider classpath 缺 io.grpc:grpc-context:1.28.0（SOFATracer 3.x 依赖它做上下文传播）。补 jar 后重启重跑，S1 通过。首次失败保留：该次输出同时证明请求已抵达 provider（responseContentLength=178）且失败路径也回带了 traceId。
2S5 的 digest 行 "baggage":"" 为空，但业务方法确实读到了 baggage观察，非缺陷 digest 的 baggage 字段记录穿透属性 sofaPenAttrs，不是 rpc_req_baggage；服务端读取路径已由 SERVER_TRACE 行证实。
3digest 行 "remote.ip":"127.0.0.1" 与发送的 sofaCallerIp（192.168.18.222）不同观察，非缺陷 服务端以实际 socket 对端地址覆盖该 tag；remote.app 仍来自我们发送的 sofaCallerApp，调用方识别不受影响。

手工顺序执行，逐步检查结果后再进行下一步；不是无人值守脚本。 harness/classpath.txt 中 ${M2} 替换为 ~/.m2/repository，${SCRATCH} 替换为工作目录。

     -Dprovider.registry.file=<tmp>/registry.local \
     com.example.demo.ProviderMain          # 等待 PROVIDER_READY

  -types java.lang.String -args '["hello"]'
